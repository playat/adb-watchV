# adb-watchV

给安卓手机发上滑 / 下滑 / 点按手势 —— 一个常驻屏幕左上角的小悬浮条，点一下，手机就动。

盯着手机刷短视频、看小说，手不用离开键盘（也不用离开鼠标）：点一下悬浮条上的 `▼`，手机就往下滑一屏。
靠 `adb shell input swipe` / `input tap` 驱动，不装任何手机端 App。

> Python + tkinter 实现。老的 PowerShell 版已经删掉，只保留这一份。

---

## 真实使用场景：工位、耳机、最暗的屏幕

先说人话，这东西到底是给谁写的。

设想一下这个画面。你在工位上，手机搁在桌角，屏幕亮度已经拉到最低 —— 低到隔壁工位瞟一眼，只看见一块快熄灭的黑玻璃。耳机塞着，屏幕里在播视频，但你压根没在看，你在听。

然后视频播完了，得滑下一条。

于是你伸手去够手机：指尖点一下、划一下。整套动作不到两秒，但**你的动作可能恰巧被老板、同事看到**。在工位上，多一个动作或者少一个动作，差别巨大 —— 这一个动作，基本等于你告诉老板、同事，你在摸鱼。

现在换个方式：手在鼠标上不动，点一下屏幕左上角那个 `▼`，手机自己滑到下一条。屏幕全程是黑的，耳机继续响着，而你的姿势从第一秒到最后一秒都只有一个含义 —— 「正在认真工作」。

> 摸鱼的最高境界，是不产生任何一个多余的动作。

（同理适用于：开会时桌子底下刷小说、床上听相声、开车等红灯…… 最后一个当我没说。）

## 快速开始

1. 手机：`设置 > 关于手机 > 连点 7 次「版本号」` 打开开发者选项
2. 手机：`设置 > 开发者选项 > 无线调试` 打开（顺手把「USB 调试（安全设置）」也打开）
3. 电脑：双击 `run.pyw`（`.pyw` 由 pythonw 执行，全程没有控制台，不会闪黑框）
4. 等它自己扫到 —— 扫到就自动连，然后左上角出现悬浮条

**启动就是一个连接窗口，它会一直扫 mDNS**，每 2.5 秒一轮，扫到立刻连、连上即停，全程不用点任何东西
（手机重开无线调试后端口变了也能自己找对）。

## 界面长什么样

### 1. 连接窗口（启动就有）

```
┌──────────────────────────────────┐
│ adb-watchV                    ●  │
│ 正在扫描 mDNS …                   │
│ 第 4 次 · 已等 9 秒 · 按 Esc 手动输入 │
└──────────────────────────────────┘
```

扫到 → 状态变成「连接 192.168.88.9:42123 …」→ 连上就收起窗口、放出悬浮条。

### 2. 按 `Esc`：窗口下面长出输入模块

```
┌──────────────────────────────────┐
│ adb-watchV                    ●  │
│ 手动连接                          │
│ 手机『无线调试』主页上的 IP:端口     │
│                                  │
│ 连接 IP:端口 [192.168.88.   ] ✓ ⟳ │
└──────────────────────────────────┘
```

输入框预填了 `192.168.88.`（内网基本都是这个开头），接着往后敲就行。
输完点右边的 **✓**（或直接按回车）才开始连 —— 它不会一边打字一边连。

点 **⟳** 就放弃手动输入，回去继续扫 mDNS（等于从头再等自动发现）。

**布局**：**输入模块永远贴在窗口底部**，状态 / 详情 / 红色报错这几行文本一多，
中间那块会自己长出竖向滚动条（滚轮也能滚），不会再把下面的输入框顶出窗口。
日常那两三行文字远远到不了上限，看不到滚动条是正常的。

**位置**：窗口**不置顶**了，会被别的窗口正常盖住。第一次出现时在屏幕正中（避开任务栏），
之后**你拖到哪它就待在哪** —— 扫描次数刷新、切手动 / 配对、窗口变高，都只改高度不挪位置。
只有一种情况会动：窗口长到超出屏幕底部时，它会往上顶一点，免得被任务栏吃掉。

### 3. 连不上：模块自动变成配对

```
┌──────────────────────────────────┐
│ adb-watchV                    ●  │
│ 配对                              │
│ 没连上。手机上点『使用配对码配对设备』 │
│                                  │
│ 配对 IP:端口 [192.168.88.9:    ]  │
│ 配对码       [              ]  ✓ │
│ ← 返回手动连接                     │
└──────────────────────────────────┘
```

手机上点「使用配对码配对设备」，照着**弹窗里**的地址和 6 位码填，点 **✓** 主动配对。
配对页那个 **⟳** 和手动页的一样，点它直接回去扫描。
配对成功后它会自己重连（mDNS 现端口 → 刚才输的端口 → 5555 依次试），连上就出悬浮条。

### 4. 悬浮操作条（默认屏幕左上角）

```
┌────┐
│ ═  │  ← 这条细边可以按住拖走
│ ▲  │  上滑
│ ●  │  点按（屏幕正中）
│ ▼  │  下滑
│ ↺  │  重启：断开重连，回到扫描
└────┘
```

- **几乎透明**：平时只有 10% 不透明度，基本只剩个影子，完全不挡视线；鼠标移上去立刻变到 98%，点得准
- **冒提示时会提亮**：10% 下文字根本看不清，所以「设备已离线」「F1 被占」这类提示一出现，
  条会临时提到 92%，提示消失后再落回 10%
- **可以拖**：按住顶部那条细边拖到任何位置；点 `↺` 重启后会回到左上角
- **右键**：重新连接 / 退出
- 手势发失败（比如手机走远了）时，条底部会出现一行红字「设备已离线」，点 `↺` 重连

`▲` / `●` / `▼` 对应老版本的三个快捷键：鼠标点，或者按下面的 `Alt+F1/F2/F3` 都行。

### 5. 键盘快捷键（和鼠标等效）

老版的全局快捷键保留了：

| 快捷键 | 动作 |
|---|---|
| `Alt+F1` | 上滑 |
| `Alt+F2` | 下滑 |
| `Alt+F3` | 点按（屏幕正中） |

- **全局生效**：别的窗口在前台也能按，不用把悬浮条切到前面
- **只在连上之后占键**：悬浮条出现时才注册，连接窗口和配对阶段不会抢键
- **点 `↺` 或退出时立刻释放**，不会留下占着却不干活的键
- **重启只有 `↺`，没有热键**：重启是个低频动作，不值得占一个全局键
- 想换键：改 `adb_watch_v.py` 里的 `HOTKEYS`，写 `"Ctrl+Alt+F1"`、`"Shift+F9"` 都可以，支持 `F1`~`F24`、单个字母 / 数字、以及 `Alt+SPACE` 这种具名键
- 某个键被别的软件占了：悬浮条底部会闪一行「热键被占用：Alt+F1」，剩下两个照常能用

## 连不上的时候它在干什么（和老版一致）

| 阶段 | 行为 |
|---|---|
| 开扫前 | `adb kill-server` —— 清掉死连接和旧 mDNS 缓存，否则会一直扫到早已失效的端口 |
| 每个地址 | 先花 1.5 秒探端口。不通就判失败，不让 `adb connect` 干等 |
| 连接 | `adb connect` 带 20 秒硬超时，到点强制结束 |
| 端口通但握不上手 | 每轮算一次，**连续 3 次**就停下扫描、直接换成配对模块 |
| 配对端口填错 | 如果你把「连接端口」填进配对框，会当场拦下（那端口是开的，但对面不是配对服务，会一直卡着） |

**插线也行，而且更省心**：USB 线插上、手机弹「允许 USB 调试」点允许，窗口会在下一轮扫描时直接用它，
不用等 mDNS，也不用配对 —— USB 端口永远不会变，Wi-Fi 断了都不影响。有线和无线可以同时连着，
这时窗口会列出所有在线设备让你点一台。

## 目录结构

```
adb-watchV\
├── run.pyw                  ← 双击这个：经 pythonw 启动，无控制台
├── adb_watch_v.py            主程序
└── adb\
    ├── adb.exe               自带的 adb，不依赖系统环境变量
    ├── AdbWinApi.dll
    └── AdbWinUsbApi.dll
```

**adb 是自带的**：优先用 `adb\adb.exe`，找不到才退回系统 `PATH`。
整个文件夹拷到任何一台装了 Python 的 Windows 电脑上都能直接跑。

## 调参

都写死在 `adb_watch_v.py` 顶部的常量里，改完重开就行：

| 常量 | 默认 | 说明 |
|---|---|---|
| `DURATION_MS` | `300` | 单次滑动持续时间。太大像拖拽，太小容易被识别成惯性甩动，`250~400` 比较稳 |
| `NEAR_RATIO` | `0.8` | 滑动起点（屏幕靠下）在屏幕高度上的比例 |
| `FAR_RATIO` | `0.2` | 滑动终点（屏幕靠上）的比例 |
| `SCAN_INTERVAL` | `2.5` | mDNS 扫描间隔（秒） |
| `BAR_ALPHA` | `0.10` | 悬浮条平时的不透明度。调到 `0` 就彻底看不见了，别这么干 |
| `BAR_ALPHA_HOVER` | `0.98` | 鼠标在条上时的不透明度 |
| `BAR_ALPHA_MSG` | `0.92` | 条上有提示文字时的不透明度，太暗的话文字读不出来 |
| `WIN_W` | `430` | 连接窗口的逻辑宽度，实际宽度会乘上屏幕的 DPI 缩放 |
| `MSG_MAX_H` | `190` | 中间文本区的最大高度（逻辑像素），超过就出滚动条 |
| `SCALE` | 自动 | 屏幕缩放比（96 DPI 为 `1.0`，你这台 150% 就是 `1.5`），启动时检测，不用改 |

滑动被识别成"甩一下"飞出去好几屏 → `DURATION_MS` 调到 `400`；反应太黏 → 调到 `250`。

## 高清屏（缩放 125% / 150% 以上）

程序启动时会声明 DPI 感知，然后按屏幕缩放比把字号和间距一起放大。

以前不声明的话，Windows 会把窗口当成 96 DPI 的位图整体拉伸 1.5 倍 —— 尺寸看着没错，
但**字全是糊的**。现在文字按真实 DPI 直接渲染，是清晰的，视觉大小和之前一致。

窗口位置固定屏幕正中（水平 + 垂直），悬浮条固定左上角。

---

## 每次启动都重新扫，不记任何东西

程序**不落盘**任何东西（没有配置文件）：

- 设备地址不记 —— 每次启动一直扫 mDNS，手机重开无线调试后端口变了也能自己找到
- 配对码不记 —— 用完立即从内存丢弃

## 常见问题

**连不上 / 一直失败？**
1. 手机和电脑在同一个 Wi-Fi 吗？
2. 手机上「无线调试」还开着吗？（锁屏久了有时会掉）
3. 端口填对了吗？**「配对端口」和「连接端口」是两个不同的随机端口**，别抄错：
   - 配对端口 → 在「使用配对码配对设备」对话框里
   - 连接端口 → 在「无线调试」主页上
4. 还不行：手机上关掉无线调试再打开，然后点悬浮条上的 `↺` 重启

**手机拿远一阵、回来重新连 Wi-Fi 之后就连不上了？**

无线调试最常见的一种"抽风"，三个原因叠加，程序都针对处理了：

| 现象 | 真正的原因 | 怎么处理 |
|---|---|---|
| 卡在「连接中」几十秒没动静 | 手机重开无线调试后**端口变了**，`adb connect` 在死等 TCP 重试 | 先探端口，不通直接说；`adb connect` 也有 20 秒硬超时 |
| 一直报「already connected」但设备离线 | adb 服务里留着上次的死连接 | 开扫前 `adb kill-server` |
| 输入全对，却**卡在配对**不动 | 把「主页的连接端口」填进了配对框 | 填之前反查已知连接端口，是就当场拦下 |

那几分钟的等待有时是手机自己在恢复（adbd 的监听 socket 要等系统重新拉起来），
电脑这边做不了什么，**关掉无线调试再打开**通常比干等快得多。

**悬浮条不见了？**
点右上角的最小化不算 —— 它可能被拖到屏幕边缘了。点 `↺` 重启会把位置重置回左上角。
另外**悬浮条**是置顶的（连接窗口不是），全屏游戏 / 远程桌面里可能被挡住，切回桌面就能看见。

**提示「拿不到分辨率」？**
`adb shell wm size` 失败了，通常说明连接是"半死"状态。点窗口里的「重试连接」，
或者连上之后点悬浮条上的 `↺` 重新走一遍。

**悬浮条点了没反应？**
看条底部有没有红字。手势发失败时它会显示「设备已离线」或「上滑失败」，那就是连接掉了 —— 点 `↺`。

**双击 `run.pyw` 什么都没发生？**
大概率是没有 Python（或 Python 没带 tkinter）。在命令行里跑 `py -3 adb_watch_v.py` 能看到具体报错；
启动失败时日志也会写到 `%TEMP%\adb-watchV-error.log`。
如果双击后弹出「选择打开方式」而不是直接运行，说明 `.pyw` 没关联到 pythonw —— 右键 `run.pyw` →
打开方式 → 选 `pythonw.exe`（在 Python 安装目录下）→ 勾「始终使用此应用」，之后就能双击了。

## 环境要求

- Windows 10 / 11
- Python 3.9+（**必须带 tkinter**，官方安装包默认就有）
- 手机开启开发者选项 + 无线调试（Android 11+ 才有无线调试的配对功能）
