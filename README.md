# adb-watchV

用键盘的 `Shift+↑` / `Shift+↓` / `Shift+空格`，给安卓手机发上滑 / 下滑 / 点按手势。

盯着手机屏幕刷短视频、看小说，手不用离开键盘 —— 按一下 `Shift+↑`，手机就往上滑一屏。
靠 Windows 全局热键驱动 `adb shell input swipe` / `input tap`，不装任何手机端 App，不依赖 USB。

---

## 真实使用场景：工位、耳机、最暗的屏幕

先说人话，这东西到底是给谁写的。

设想一下这个画面。你在工位上，手机搁在桌角，屏幕亮度已经拉到最低 —— 低到隔壁工位瞟一眼，只看见一块快熄灭的黑玻璃。耳机塞着，屏幕里在播视频，但你压根没在看，你在听。

然后视频播完了，得滑下一条。

于是你伸手去够手机：指尖点一下、划一下。整套动作不到两秒，但**你的动作可能恰巧被老板、同事看到**。在工位上，多一个动作或者少一个动作，差别巨大，尤其是你的工位不太好摸鱼的请看下，这一个动作，基本等于你告诉老板、同事，你在摸鱼。

现在换个方式：手摆在键盘上不动，敲一下 `Shift+↓`，手机自己滑到下一条。屏幕全程是黑的，耳机继续响着，而你的姿势从第一秒到最后一秒都只有一个含义 —— 「正在认真工作」。

> 摸鱼的最高境界，是不产生任何一个多余的动作。

（同理适用于：开会时桌子底下刷小说、床上听相声、开车等红灯……最后一个当我没说。诶，说不定可以，嘿嘿）

## 快速开始

1. 手机：`设置 > 关于手机 > 连点 7 次「版本号」` 打开开发者选项
2. 手机：`设置 > 开发者选项 > 无线调试` 打开，注意，最好打开USB调试（安全设置）
3. 电脑：双击 `start-watchV.cmd`
4. 跟着提示选设备 / 输地址，连上后就能按快捷键了

| 按键 | 动作 |
|---|---|
| `Shift+↑` | 上滑（手指从屏幕下方划到上方，内容往上滚） |
| `Shift+↓` | 下滑（反过来） |
| `Shift+空格` | 在屏幕**正中点一下** —— 相当于轻点屏幕中央，用来暂停 / 点赞 / 点开当前那条 |

关掉窗口（或 `Ctrl+C`）即停止，热键自动释放，不留后台进程。

## 统计

每次动作**不刷日志** —— `adb shell input swipe` / `input tap` 成功时本来就不输出任何东西，静默才是正常。

累计次数固定在**输出的最后一行**，每按一次就**原地重写那一行**，不新增任何输出行，
所以按一百次屏幕也不会被刷满：

```
[15:40:12] adb：C:\tools\adb-watchV\adb\adb.exe  (脚本自带)
[15:40:14] 正在(全局)监听 Shift+↑ 上滑 / Shift+↓ 下滑 / Shift+空格 点按 ... 关窗口或 Ctrl+C 停止
adb-watchV  |  上滑 12   下滑 8   点按 3     ← 就是这一行，一直在最后，原地刷新
```

`Ctrl+C`（或关窗口）停止时，统计行让位，换成一行合计：

```
[15:42:07] 已停止监听，热键已释放。
[15:42:07] 本次共滑动 20 次（上滑 12 / 下滑 8），点按 3 次
```

只有动作**真的失败**时才会插一条消息（附上 adb 原始输出），免得错误被无声吞掉 ——
这种情况统计行会被往下挤一行，继续待在最后。

计数只活在本次会话里，关掉窗口就清零 —— 想统计"今天一共滑了多少条"，就开着窗口别关。

## 目录结构

```
adb-watchV\
├── start-watchV.cmd           ← 双击这个
├── adb-watchV-hotkey.ps1      主脚本，真正干活的
├── adb-watchV.config.json     记住上次用过的设备（自动生成）
└── adb\
    ├── adb.exe                 自带的 adb，不依赖系统环境变量
    ├── AdbWinApi.dll
    └── AdbWinUsbApi.dll
```

**adb 是自带的**：脚本优先用 `adb\adb.exe`，找不到才退回系统 `PATH`（并给一句黄色提醒）。
所以整个文件夹拷到任何一台 Windows 电脑上都能直接跑，不需要事先装 platform-tools。

## 参数

双击启动时传不了参数。想用参数就在控制台里跑：

```bat
start-watchV.cmd -Setup
start-watchV.cmd -Device 192.168.88.22:43921
start-watchV.cmd -ConsoleOnly
start-watchV.cmd -Device 192.168.88.22:43921 -Duration 250 -NearRatio 0.75
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Device <地址>` | 空 | 直接指定设备（`adb devices` 里那一列），不弹菜单、不走引导 |
| `-Setup` | — | 跳过设备菜单，直接进「连接新设备」的三连尝试 |
| `-Duration <ms>` | `300` | 单次滑动持续时间。太大像拖拽，太小容易被识别成惯性甩动，`250~400` 比较稳 |
| `-NearRatio <0~1>` | `0.8` | 滑动起点（近端，屏幕靠下）在屏幕高度上的比例 |
| `-FarRatio <0~1>` | `0.2` | 滑动终点（远端，屏幕靠上）的比例 |
| `-ConsoleOnly` | — | 只监听本窗口有焦点时的按键，不抢系统热键 |

**调参建议**
- 滑动被识别成"甩一下"就飞出去好几屏 → `-Duration` 调大到 `400`
- 反应太黏、不跟手 → `-Duration` 调小到 `250`
- 滑动距离太短 / 太长 → 调 `-NearRatio` 和 `-FarRatio`

## 配置文件

`adb-watchV.config.json`（脚本同目录，自动生成）：

```json
{
  "device": "192.168.88.22:43921",
  "savedAt": "2026-10-15 14:29:04"
}
```

只存**设备地址**，作用是在设备菜单里把它设为默认高亮项 —— 下次启动直接回车即用。

**配对码绝不落盘**：用完立即从内存丢弃，日志里打印的也是 `******`。

删除这个文件 = 清空记忆，回到完全手动。

## 常见问题

**连不上 / 一直失败？**
1. 手机和电脑在同一个 Wi-Fi 吗？
2. 手机上「无线调试」还开着吗？（锁屏久了有时会掉，你频繁开关的话更要留意）
3. 端口填对了吗？**「配对端口」和「连接端口」是两个不同的随机端口**，别抄错：
   - 配对端口 → 在「使用配对码配对设备」对话框里
   - 连接端口 → 在「无线调试」主页上
4. 还不行：手机上关掉无线调试再打开，然后重跑脚本

**端口每次都不一样？**
正常。Android 无线调试的连接端口是**每次重开都随机变**的。已经配对过的设备，重连时往往只需重走 `[2/3] 手动输入`，不用重新配对（配对码是另一回事，一次性）。

**提示「地址不对」？**
输入框预填了 `192.168`（内网基本都是这个开头），**接着往后敲**就行 ——
别习惯性从头发一遍完整 IP，那会拼成 `192.168192.168...`，脚本会拦下来重问。

**菜单里出现两个条目指向同一台手机？**
Android 11+ 的常见现象：`adb connect` 注册一条、mDNS 自动连接又注册一条。脚本会自动去掉 mDNS 别名那条（`._adb-tls-connect._tcp` 结尾的）。

**方向键菜单没反应 / 乱码？**
必须在**真实控制台窗口**里跑（双击 `start-watchV.cmd`）。
用管道调用（`start-watchV.cmd | something`）时 `ReadKey` 会失效，脚本检测到输入被重定向会降级处理。

**按 `Shift+空格` 没反应，或者启动时提示注册失败？**
中文输入法把 `Shift+空格` 用作全角 / 半角切换，可能抢在前面。三种处理：
1. 临时切到英文输入法（脚本注册成功后，热键是全局的，输入法状态不影响它）
2. 用 `-ConsoleOnly` 启动，只在控制台有焦点时生效，跟输入法井水不犯河水
3. 干脆不用这个键 —— 上滑 / 下滑不受影响，脚本照常跑

## 环境要求

- Windows + PowerShell 5.1（系统自带，无需额外安装）
- 手机开启开发者选项 + 无线调试（Android 11+ 才有无线调试的配对功能）
- 无需安装 Python、Node、AutoHotkey 或任何第三方运行时
