# adb-swipe

用键盘的 `Shift+↑` / `Shift+↓`，给安卓手机发上滑 / 下滑手势。

盯着手机屏幕刷短视频、看小说，手不用离开键盘 —— 按一下 `Shift+↑`，手机就往上滑一屏。
靠 Windows 全局热键驱动 `adb shell input swipe`，不装任何手机端 App，不依赖 USB。

---

## 快速开始

1. 手机：`设置 > 关于手机 > 连点 7 次「版本号」` 打开开发者选项
2. 手机：`设置 > 开发者选项 > 无线调试` 打开
3. 电脑：双击 `start-swipe.cmd`
4. 跟着提示选设备 / 输地址，连上后就能按 `Shift+↑` `Shift+↓` 了

关掉窗口（或 `Ctrl+C`）即停止，热键自动释放，不留后台进程。

## 目录结构

```
adb-swipe\
├── start-swipe.cmd            ← 双击这个
├── adb-swipe-hotkey.ps1       主脚本，真正干活的
├── adb-swipe.config.json      记住上次用过的设备（自动生成）
└── adb\
    ├── adb.exe                 自带的 adb，不依赖系统环境变量
    ├── AdbWinApi.dll
    └── AdbWinUsbApi.dll
```

**adb 是自带的**：脚本优先用 `adb\adb.exe`，找不到才退回系统 `PATH`（并给一句黄色提醒）。
所以整个文件夹拷到任何一台 Windows 电脑上都能直接跑，不需要事先装 platform-tools。

## 连接流程

启动后先看 `adb devices` 里有没有已经在线的设备。

**已经有设备** → 弹方向键菜单（`↑/↓` 移动，回车确认，`Esc` 取消）：

```
adb 里检测到 2 台可用设备，请选择：
  ↑/↓ 移动，回车确认，Esc 取消
  192.168.88.22:43921          25098PN5AC     ← 上次用过的，默认高亮
  emulator-5554                sdk_gphone
  ABC123XYZ                    未授权          ← 列出来但选不中
  连接新设备…
```

选已在线设备 → 直接进监听。选最后一项「连接新设备…」→ 进下面的三连尝试。

**没有设备** → 三连尝试，一次比一次多问一点，**能少问就少问**：

```
[1/3] mDNS 自动发现
      扫描局域网里的无线调试广播，列出来让你选
        没有 / 失败 ↓

[2/3] 手动输入连接地址
      手机『无线调试』主页上那行 IP:端口
        失败 ↓

[3/3] 配对
      手机『使用配对码配对设备』对话框里的 IP:端口 + 6 位码
      adb pair → 再 connect
```

### 为什么 mDNS 要等

`adb mdns services` 在你**刚打开无线调试的瞬间经常是空的** —— 手机的 mDNS 广播有延迟，要几秒才发得出来。
所以第 1 步不是"扫一次就走"，而是**扫一次、空就隔一秒重扫，最多等 6 秒**，一有结果立刻停。

### 为什么配对放在最后

配对码是**一次性**的（对话框关掉就失效），而且每次都得手动打开那个对话框，是成本最高的操作。
所以只有前两次连接都失败了才走到配对 —— 大多数时候你根本碰不到它。

## 快捷键

| 按键 | 动作 |
|---|---|
| `Shift+↑` | 上滑（手指从屏幕下方划到上方，内容往上滚） |
| `Shift+↓` | 下滑（反向） |
| `Ctrl+C` | 停止监听并退出 |

按住不放会连续滑动。

> ⚠️ **默认是全局热键**：脚本运行期间，`Shift+↑` / `Shift+↓` 在**整个系统**都被本脚本吃掉 ——
> 包括 VS Code 里的「选中到文档头 / 尾」。
> 不想影响其它软件，就用 `-ConsoleOnly`（见下）。

## 参数

双击启动时传不了参数。想用参数就在控制台里跑：

```bat
start-swipe.cmd -Setup
start-swipe.cmd -Device 192.168.88.22:43921
start-swipe.cmd -ConsoleOnly
start-swipe.cmd -Device 192.168.88.22:43921 -Duration 250 -NearRatio 0.75
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Device <地址>` | 空 | 直接指定设备（`adb devices` 里那一列），不弹菜单、不走引导 |
| `-Setup` | — | 跳过设备菜单，直接进「连接新设备」的三连尝试 |
| `-Duration <ms>` | `300` | 单次滑动持续时间。太大像拖拽，太小容易被识别成惯性甩动，`250~400` 比较稳 |
| `-NearRatio <0~1>` | `0.8` | 滑动起点（近端，屏幕靠下）在屏幕高度上的比例 |
| `-FarRatio <0~1>` | `0.2` | 滑动终点（远端，屏幕靠上）的比例 |
| `-ConsoleOnly` | — | 只监听本窗口有焦点时的按键，不抢系统热键 |

**调参建议**
- 滑动被识别成"甩一下"就飞出去好几屏 → `-Duration` 调大到 `400`
- 反应太黏、不跟手 → `-Duration` 调小到 `250`
- 滑动距离太短 / 太长 → 调 `-NearRatio` 和 `-FarRatio`

## 配置文件

`adb-swipe.config.json`（脚本同目录，自动生成）：

```json
{
  "device": "192.168.88.22:43921",
  "savedAt": "2026-10-15 14:29:04"
}
```

只存**设备地址**，作用是在设备菜单里把它设为默认高亮项 —— 下次启动直接回车即用。

**配对码绝不落盘**：用完立即从内存丢弃，日志里打印的也是 `******`。

删除这个文件 = 清空记忆，回到完全手动。

## 常见问题

**连不上 / 一直失败？**
1. 手机和电脑在同一个 Wi-Fi 吗？
2. 手机上「无线调试」还开着吗？（锁屏久了有时会掉，你频繁开关的话更要留意）
3. 端口填对了吗？**「配对端口」和「连接端口」是两个不同的随机端口**，别抄错：
   - 配对端口 → 在「使用配对码配对设备」对话框里
   - 连接端口 → 在「无线调试」主页上
4. 还不行：手机上关掉无线调试再打开，然后重跑脚本

**端口每次都不一样？**
正常。Android 无线调试的连接端口是**每次重开都随机变**的。已经配对过的设备，重连时往往只需重走 `[2/3] 手动输入`，不用重新配对（配对码是另一回事，一次性）。

**提示「地址不对」？**
输入框预填了 `192.168`（内网基本都是这个开头），**接着往后敲**就行 ——
别习惯性从头发一遍完整 IP，那会拼成 `192.168192.168...`，脚本会拦下来重问。

**菜单里出现两个条目指向同一台手机？**
Android 11+ 的常见现象：`adb connect` 注册一条、mDNS 自动连接又注册一条。脚本会自动去掉 mDNS 别名那条（`._adb-tls-connect._tcp` 结尾的）。

**方向键菜单没反应 / 乱码？**
必须在**真实控制台窗口**里跑（双击 `start-swipe.cmd`）。
用管道调用（`start-swipe.cmd | something`）时 `ReadKey` 会失效，脚本检测到输入被重定向会降级处理。

## 环境要求

- Windows + PowerShell 5.1（系统自带，无需额外安装）
- 手机开启开发者选项 + 无线调试（Android 11+ 才有无线调试的配对功能）
- 无需安装 Python、Node、AutoHotkey 或任何第三方运行时

## 原理

```
键盘按键
   ↓
RegisterHotKey (user32.dll)  ← 全局热键，窗口失焦也能收
   ↓
adb shell input swipe <x1> <y1> <x2> <y2> <时长>
   ↓
手机执行滑动手势
```

滑动坐标根据设备分辨率算：取屏幕竖直中线做 `x`，`y` 用屏幕高度的 80% / 20% 两个点，
所以不同分辨率的手机都能用，不用改脚本。
